## Defects reproduced and corrected

Before changes, targeted tests showed that (1) the evaluator accepted shortened rankings as valid zero scores; (2) split/paired aggregation accepted altered user/label denominators; (3) the coordinator exposed only combined strategy costs and no failure location; and (4) the live canonical source could be modified after replay freeze without an explicit source hash check in serving/evaluator paths. The cache loader allowed an unanchored manifest argument; an attacker could present mutually consistent altered tensor and manifest bytes under the same identity. These were concrete trust-boundary or scientific-accounting defects, not style changes.

The smallest repairs were: require exactly `min(20, unmasked catalog)` ranked items; carry `labels_sha256` into user rows and compare user/window denominators before aggregation; require external manifest SHA-256 on every cache load; recheck canonical source SHA before querying it; reject a future-label-bearing `QualityBundle` before strategy preparation; record replay initialization, strategy-specific timing, cache disposition, quality-bundle time and failure context. S2 popularity count setup now has an explicit timer. D2 cache test callers now pass the published SHA. The fixture's second user was moved outside the prior-90-day period and given an unseen low rating so the selector and mask assertions actually distinguish the intended cases. No optimizer path, model architecture change, new strategy or protocol change was introduced.

The independent graph reference rebuilds each projection from canonical events, then checks exact edges/degrees and normalized COO weights. A separate hand calculation uses one user with relevant movie 20 ranked second: Recall@20 = 1 and NDCG@20 = `1/log2(3)`. The toy result matches that calculation. Before January, independently expected unique-user popularity for movies 10/20/30 is 1/2/1. These checks avoid using the production metric and baseline to certify themselves.

History is strictly `<b`; labels are `[b,e)`. Tied rows at `b` have consecutive canonical IDs and are absent from the frozen graph. A repeated positive contributes one edge and one unique label pair. Low ratings neither mask unseen movies nor remove earlier positive edges. All three strategies receive the same `BoundaryHistory`, catalog, mask and IDs; quality is constructed only after the serving-like state/ranking. A label-bearing bundle is rejected by strategy preparation before any forward. A corrupted source, cache, snapshot, label denominator or catalog is rejected rather than reconciled. No sampled negatives enter official ranking semantics. The approved full-source SHA is provenance; it is allowed to change the cache key when source bytes change.

For the two-boundary toy: P0 setup = **1** attempted forward total, S1 = **6** attempts (two boundaries × three repetitions), S0 after P0 = **0**, S2 = **0**, optimizer updates = **0**. ## Teaching note

*Temporal leakage* là dùng thông tin của tương lai để tạo khuyến nghị ở quá khứ. Ví dụ: rating ngày 01/01/2021 không được thêm vào graph hoặc mask ngay tại đầu ngày 01/01; nó chỉ là nhãn để chấm tháng 1, rồi mới thành lịch sử ở boundary tháng 2. Nếu dùng rating ấy để chọn user benchmark tháng 1, phép so sánh đã bị lộ tương lai.

*Oracle độc lập* là một cách tính tham chiếu khác đường code đang kiểm. Nếu hai hàm cùng gọi một helper sai, chúng vẫn có thể cho cùng kết quả sai. Ở đây graph được dựng lại từ đầu và NDCG được tính tay, nên có thể phát hiện lỗi mà test tự so sánh không thấy.

SHA-256 khớp chứng tỏ bytes của checkpoint, snapshot hoặc cache đúng với bản đã ghi nhận. Chỉ khớp tên file không đủ: file có thể bị thay nhưng giữ nguyên tên. SHA của manifest cache còn cần một giá trị tham chiếu bên ngoài chính cache đó; nếu không, người ta có thể sửa cả tensor lẫn manifest cho khớp nhau.

Test correctness trả lời “logic có đúng trên trường hợp kiểm được không?”. Benchmark performance trả lời “chạy trên dữ liệu/hardware thực tốn bao lâu và bao nhiêu RAM?”. D3 phải đi trước Kaggle preflight để tránh chi phí GPU/5M edges cho một thuật toán đang sai hoặc đang dùng nhãn tương lai. Toy PASS không chứng minh tốc độ thực tế.

Tự kiểm tra: (1) Rating đúng timestamp `b` thuộc graph trước `b` hay nhãn `[b,e)`? (2) Vì sao phải giữ SHA manifest ở ngoài thư mục cache? (3) Một toy test PASS có chứng minh giới hạn 30 giờ trên GPU không?
